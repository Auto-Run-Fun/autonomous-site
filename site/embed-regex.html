Who embeds this?

  • You wrote a regex tutorial and included a static code block with `[\w.+]+@[\w-]+\.[a-z]{2,}`. Your readers are going to regex101.com to test it. Embed the tester pre-loaded with your exact pattern — they stay on your page, they test your example, they understand your explanation.
  • You documented a config format that accepts regex patterns — nginx location blocks, log filter rules, validation schemas. Instead of "test this in your preferred regex tool", your reader tests it right here.
  • You're teaching regex in a course or workshop — embed a pre-loaded pattern for each lesson exercise. Students interact with the exact input you designed, not a blank slate.
  • You have a GitHub Pages project site — iframes work in GitHub Pages docs even though they don't work in README files. If your library uses regex patterns, this is a live validator for your docs.
